Spec — MCP server (Claude ↔︎ the app)

Lets Claude (Claude Code / Claude Desktop, later claude.ai) drive the content creator: import footage, search the library, assemble edits — from a chat, in the user's own words. Core shipped 2026-07-17; this spec covers the design of record plus the unbuilt roadmap. Per CLAUDE.md, delete this file when the roadmap below is done; strike the ROADMAP line as each phase ships.

Principle: thin proxy, one source of truth

The MCP server (editor/mcp_server.py) is a thin proxy over the running Flask app — every tool calls the same HTTP endpoints the desktop UI uses. It holds no business logic and never touches the DB directly.

Claude (chat) ──stdio──▶ mcp_server.py ──HTTP──▶ Flask app ──▶ editor.db
                                                     ▲
                                       desktop UI ───┘ (same backend)

Why this shape, and not an MCP that imports the app's modules or hits SQLite:

  • No drift. The UI and Claude exercise identical code paths; a fix in a route fixes both. There is exactly one place business logic lives.
  • Propagation is free. A write from Claude lands in the shared editor.db; the desktop editor's live-refresh poll surfaces it with no reload (see app.js pollForNewEdits). "Ask here → watch it appear there" needs no cross-process messaging.
  • Cost: the app must be running. Mitigated by auto-start (below).

Non-negotiables for any new tool: it MUST go through an existing HTTP endpoint. If no endpoint fits, add the endpoint (thin route + logic in the owning module) first, then have the tool call it. Never reach into db.py/core.py from the MCP.

Shipped (2026-07-17)

  • Transport & entry point. stdio via FastMCP; content-creator-mcp console script (editable install resolves back to the repo so auto-start finds app.py).
  • Config. EDITOR_URL (default http://127.0.0.1:5001), MCP_AUTOSTART (default on) — starts the app headless as a detached child and waits for /api/env health, but only when EDITOR_URL is localhost.
  • App-down path. Tools raise a clear "launch the app" message, never a stack trace.
  • Tools (all proxy existing endpoints):
    • import_media(paths?, drive_links?, photos_links?) → /api/import-files (multipart; handles zips) + /api/drive-import + /api/photos-import; polls the async import job to completion.
    • search_clips(query) → /api/clips?q= (subset of fields incl. index_status).
    • redownload_clip(clip_id) → /api/clips/<id>/pull; re-fetches a "not local" clip from its recorded source and polls the job (idempotent).
    • assemble_cut(prompt, clip_ids?, campaign_id?, name?) → /api/generate-edit; returns the new edit id, its campaign, concept, and selections.
  • Registration. Project-scoped .mcp.json at repo root with relative paths (portable across clones/usernames); README documents the clone → pip install -e → .env → register flow, incl. the Claude Desktop absolute-path variant.

Currency & known gaps (2026-07-17 audit)

Because the MCP is a thin proxy, backend features split into "inherited free" vs "needs a tool" — worth tracking so gaps are deliberate, not rediscovered.

  • Inherited free (no MCP change): aspect-from-prompt + subject-tracking framing now flow through assemble_cut (it calls /api/generate-edit); its docstring was updated 2026-07-17 to say so. Same story for core-split, migrations, and the shared error handler — internal changes the proxy is immune to. Watch: new capabilities can land silently under an existing tool, so tool docstrings drift toward understating what they do — re-read them when the underlying endpoint gains behavior.
  • Shipped but intentionally NOT exposed: the whole publishing/campaign surface (/api/campaigns/<id>/posts, /posts/<id>, publish-now, cancel, metrics/refresh, summary, arm) — deferred to roadmap A because real posting is irreversible and must keep the SOCIAL_DRY_RUN + arm gating. Do not add a publish tool before social-adapters C is live-verified.
  • Small safe gap: POST /api/clips/<id>/pull has no tool. ✅ Shipped 2026-07-17 — redownload_clip(clip_id) proxies the pull endpoint, handles the already-local short-circuit, and polls the re-download job to completion. Idempotent, no external side effects.
  • Contract drift to watch: the project_id→campaign_id rename is now reconciled end to end — the MCP sends campaign_id, /api/generate-edit reads campaign_id, and tools return edit_id/campaign_id (verified 2026-07-17). The remaining risk is the pending edits→cuts rename: these return keys and the edit/campaign vocabulary are inside its blast radius, so if that lands the MCP tool contracts change with it.

Terminology (matches the app)

Campaign (theme, e.g. "Holiday campaign") groups edits; an edit is one assembled cut; clips are the footage. The wire param and return key are both campaign_id (the older project_id name is fully retired from the MCP surface and /api/generate-edit). Note the DB table is still projects — a future edits→cuts / projects→campaigns schema rename would ripple here.

Unbuilt roadmap

Ship each phase before starting the next; delete this file when all are done.

A — Multi-account posting (depends on social-adapters C)

Today Composio is hardcoded to one user_id (DEFAULT_USER_ID) and execute_action doesn't select among connected accounts, so it's effectively single-account. Design of record: bind one Instagram account per campaign.

  • Persist connected accounts (small table or connected_accounts.list), each with the Composio connected_account_id and a friendly handle.
  • Attach an account to a campaign; posting a cut auto-targets that campaign's account (fall back to an explicit picker when unbound).
  • execute_action(..., connected_account_id=…) so the target is never ambiguous.
  • MCP surface: list_accounts, publish_edit(edit_id, account?/campaign-derived) — but only once social-adapters C is live-verified (real posting is irreversible; keep SOCIAL_DRY_RUN gating).

Decision D5, answered by the owner 2026-07-27: Claude SHOULD be able to post via MCP — a full publish_edit tool, not schedule-only. The existing rails are the permission model and are not weakened by this: the tool refuses unless the target campaign is already armed (arming stays a UI act by the owner, per campaign) and SOCIAL_DRY_RUN is off; it publishes exactly one post per call, never auto-retries (check external_id first), and surfaces failures on the post. A schedule_post tool (queue a draft/scheduled post) is unrestricted by arming since scheduling is reversible — cancel exists. Build order unchanged: nothing ships before social-adapters C is live-verified.

B — More tools (as endpoints stabilize) ✅ Shipped 2026-07-28

All shipped as thin proxies (verified live): list_campaigns, create_campaign(name, description?), list_edits(campaign_id?), get_edit(edit_id) (full detail + timeline items), revise_edit(edit_id, instruction) (edit-chat, snapshots for undo), export_edit(edit_id) (renders to clips_out/, polls the job), suggest_content. Server now exposes 11 tools total. Endpoints reconciled to the post-refactor names (/api/campaigns, /api/edits?campaign=, /api/edits/<id>/chat, /api/edits/<id>/export).

C — Distribution (packaging → PyPI)

pyproject.toml already makes pip install -e . work. To enable clone-free install (uvx content-creator-mcp): publish to PyPI. Note the auto-start assumes app.py is a sibling of the installed module — verify this holds (or degrade gracefully to "start the app yourself") for a non-editable install.

D — Remote MCP (only if sharing one hosted library)

The local proxy serves the "each user runs their own instance" model. Sharing one library with others means a hosted server behind a URL with auth (the claude.ai "add by link" model): deploy the app + MCP, add OAuth/token auth, scope access. Larger lift — hosting, auth, exposing footage. Not planned unless a hosted, multi-user product is wanted.

Testing

The MCP is a proxy, so the Priority-1 endpoint suite already covers the logic each tool exercises. Add MCP-level coverage only for proxy-specific behavior: app-down message, import-job polling/timeout, and the campaign_id mapping. Never let an MCP test hit a real Composio account or post for real.
