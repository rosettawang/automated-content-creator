Bottlenecks (what blocks what)

  • instagram-go-live is the single biggest bottleneck: real posting, platform-links' published state, mcp-server's posting tools, and analytics on real data all sit behind it. Revised 2026-07-27: it is not "one session + one click" — a run surfaced four blockers, three now fixed in code. What remains is queue #5 (the API key) then the owner's publish.
  • Do not chase the IG user id through a Meta developer app — that detour was tried and is a dead end. Composio's Instagram toolkit authenticates via Instagram Login (base_url: graph.instagram.com, current-user endpoint /me?fields=id,username), not Facebook Login, so a Facebook Page token is the wrong key; Meta also refuses to add Instagram use cases to a Facebook-Login app. The id is also absent from the connection metadata (extra_data is empty) and the stored token is Composio-proxied, so direct Graph calls fail "Cannot parse access token". Correct routes: the Composio tools.proxy call (needs queue #5), or paste the number into IG_USER_ID in editor/.env.
  • Composio gotchas that will bite any adapter: toolkit versions must be pinned as a bare datestamp (20260721_00) — latest raises ToolVersionRequiredError and a v prefix makes every slug 404 as "Tool not found". API-key scopes cannot be edited after creation.
  • platform-links ↔ social-adapters touch the same social/ files — sequence, don't parallelize.
  • import-unified and the framing tail are unblocked and parallel-safe with everything.

How to run a batch

  1. Tell Claude "work the login queue" — it opens one tab per row via the Chrome extension and drives each to the state in "Claude drives to…".
  2. You go tab to tab: sign in where needed, click the confirming button.
  3. Claude verifies the result (post visible, connection ACTIVE, import completed), strikes the row here, and updates the owning spec/ROADMAP.
